# BinderClip Agent Guide

- Keep changes separated by concern: protocol/features, networking, storage, and tooling.
- Update this file when an essential project convention, build command, or architecture detail changes. Keep it concise.
- macOS debug install: `./macos/debug-install.sh`.
- macOS production package: `./macos/package-release.sh`; it bundles Sparkle 2 and creates an ad-hoc signed universal ZIP, DMG, and signed appcast.xml using BWS secrets.
- macOS tests: `swift test --package-path macos/BinderClipMac`. Roster tests use a temp directory so they never rotate the live pairing key in Application Support.
- Android tests: `./android/gradlew -p android test`.
- Android local Gradle verification uses Java 21 (`JAVA_HOME=$HOME/.local/share/mise/installs/java/21.0.2`); Java 26 fails Android SDK JDK-image transforms.
- Star topology: macOS runs a permanent `NWListener` WebSocket server (`WebSocketServer`) on port `39421`; Android is a resilient client (`WebSocketClient`) with a single exponential backoff (`1s -> 2s -> … -> 16s`). Connection presence is live-only (never persisted). A session is alive only if it is authenticated, its bound local IPv4 still exists, and an application JSON heartbeat (`ping`/`pong` every 2s) has been heard within 5s while the phone is interactive, or 45s after a `power`/`sleep` frame. Unauthenticated sockets are cancelled after 2s. A successful auth cancels handshake leftovers and the previous session for that phone so LAN and mesh twins cannot both stay up. The listener retries with the same 1s–16s backoff if bind fails. Mac watches interface IPv4 via `SCDynamicStore` (split-tunnel VPN does not change the default `NWPath`) and evicts only sessions whose bound address disappeared — it does not mass-cancel on default-path loss. There is no mesh/chain, no Android hosting, and no Mac-as-client join path.
- Pairing: Mac **Add Device** QR is `binderclip://pair` with a URL-safe Base64 PSK and up to four sorted IPv4 endpoints (LAN, then Tailscale `100.x`, then other unicast). Never advertise loopback. Unpairing a phone sends an `unpair` frame first so the phone clears its PSK, then forgets it on the Mac. A later reconnect is ignored until that phone scans the QR again (`pairing` on auth). **Reset pairing key** notifies connected phones the same way, then rotates the PSK.
- Multi-endpoint racing (Happy Eyeballs): Android races last-good endpoint first, then advertised candidates, one socket per address (8s connect budget). The first TCP open sends auth and cancels the rest so LAN and mesh cannot dual-authenticate. Mac ignores auth on sockets already dropped from `activeSessions`. Reconnect watches Wi-Fi/Ethernet/VPN without requiring `INTERNET` (2s debounce). Heartbeat death reconnects immediately; “could not reach Mac” is only announced after backoff has reached 8s.
- Dynamic discovery: the Mac advertises its listener as Bonjour `_binderclip._tcp` with TXT `id`/`name`/`v` (re-registered on rename). Android NSD runs only while paired and disconnected (paused while connected and after unpair); a resolved service is accepted only if TXT `id` matches the paired peer id or is absent (legacy), contributes IPv4 non-loopback candidates through the normal merge/racer path, and never overrides PSK auth.
- Text and browser URLs are UTF-8 JSON frames; PNG/JPEG/WebP/HEIC images (up to 30 MiB) are atomic binary WebSocket messages (`[4-byte metadata length] + [JSON header] + [Raw image bytes]`). Device rename is a JSON `rename` frame; Mac applies it to the roster and fans it out to other sessions. The wire is cleartext `ws://` on a trusted LAN/VPN; the PSK gates who may connect.
- Clipboard classification is fail-closed: file URLs take precedence over TIFF/icons/text, but only supported image files are sent. All other files are ignored and must never be coerced into a filename string.
- Single-variable SHA-256 hash checking prevents clipboard echo loops. Unpairing clears local paired state while preserving the stable local identity.
- Android’s share target accepts supported images and text/URLs. It offers an interactive device picker to choose the target device (or all devices); when sharing a web URL (`http://`/`https://`), BinderClip sends an `openUrl` command that automatically launches the default browser on the target device. Incoming `openUrl` on Android cannot start a browser from the background service; it posts a **Browser Links** notification that opens the URL on tap. Copying a web URL onto the clipboard stays a `clipboard` frame (no Browser Links notification); `openUrl` is only for the share target and Mac **Send browser tab**. Automatic clipboard sync uses the app-owned root bridge for text/images only after KernelSU/Magisk grants `su`; it then grants BinderClip `READ_CLIPBOARD_IN_BACKGROUND` and revokes it when the toggle turns off. Otherwise it uses the user-enabled `ClipboardAccessibilityService` for text only. That service must remain clipboard-only: no window retrieval, gestures, or accessibility-event interpretation. While paired, the accessibility service also starts `BinderClipService` when Android binds it after boot.
- `BinderClipService` is a `specialUse` foreground service (persistent LAN/VPN WebSocket clipboard sync), not `dataSync`, so it is not subject to the Android 15 6-hour timeout and may start after `BOOT_COMPLETED`. `BootReceiver` starts it after boot, OEM quick-boot, or an app update when the phone is paired. After KernelSU/Magisk grants `su` while paired, BinderClip whitelists Doze/AppOps and installs `/data/adb/service.d/binderclip.sh` (plus `boot-completed.d` when that directory exists) so OEM autostart blockers cannot drop the service; unpairing removes the script.
- Android background help may request the standard battery-optimization allowlist and open App Info for OEM Auto Start controls. Manufacturer-specific auto-start intents (Xiaomi/MIUI, OPPO/ColorOS, Vivo, Huawei/Honor, OnePlus/Realme) are attempted with `resolveActivity` checks and `try-catch` fallback to `ACTION_APPLICATION_DETAILS_SETTINGS`. Do not hardcode private intents without fallback.
- On macOS, list blocking Local Network and (macOS 15.4+) denied Clipboard Access at the top of the status menu. Launch at Login is an opt-in under **More**, not a permission nag. Local Network privacy is tracked reliably in distribution only with an Apple-issued signing identity; do not claim a denied/allowed state before Network.framework reports it. The status menu lists phones only (not This Mac); **Reset pairing key**, logs, and updates live under **More**. The status item is template-safe and dims when no session is connected.
- Store CI credentials in BWS first; GitHub Actions should use only the BWS access token to load project secrets at runtime. Do not commit or print secret values.
- Do not revert unrelated worktree changes.
