# BinderClip Agent Guide

- Keep changes separated by concern: protocol/features, networking, storage, and tooling.
- Update this file when an essential project convention, build command, or architecture detail changes. Keep it concise.
- Production/debug isolation: see `docs/debug-isolation.md`. Debug Android is `net.wastu.binderclip.debug`; Mac remains `net.wastu.binderclip.debug.mb` with a new `.isolated` preferences suite, separate secrets, port 39422, `_binderclip-dbg._tcp`, custom BLE UUIDs, pairing scheme, and authenticated crypto domain. Debug uses a private clipboard and needs no root. Debug Bluetooth is off by default on both platforms and cannot automatically enable the shared radio; opt in only for dedicated Bluetooth acceptance, since simultaneous Mac advertisements can overflow Android-discoverable data. Never stop/reinstall production, copy its keys, operate its boot scripts, or use global radio/Doze changes during routine debug testing.
- macOS debug install: `./macos/debug-install.sh`. Its Services entry is **Send to Phones via BinderClip Debug**, with a distinct port name, so it cannot launch production by mistake. Ad-hoc rebuilds can trigger a fresh macOS Bluetooth permission prompt; resolve that prompt before physical tests.
- macOS production package: `./macos/package-release.sh`; it bundles Sparkle 2 and creates an ad-hoc signed universal ZIP, DMG, and signed appcast.xml using BWS secrets.
- Releases support independent platform tags (`macos-v*`, `android-v*`) and unified `v*` tags with automated diff-based change detection so folder-specific changes only build and release the affected platform while preserving the Sparkle appcast feed.
- macOS tests: `swift test --package-path macos/BinderClipMac`. Roster tests use a temp directory so they never rotate the live pairing key in Application Support.
- Android tests: `./android/gradlew -p android testDebugUnitTest`; CI also builds/lints debug artifacts and checks their merged manifest.
- Android local Gradle verification uses Java 21 (`JAVA_HOME=$HOME/.local/share/mise/installs/java/21.0.2`); Java 26 fails Android SDK JDK-image transforms.
- Star topology: macOS hosts WebSocket port `39421`; Android races mesh/LAN endpoints. Mac suspends listener, clipboard polling, advertising, sessions, and maintenance on `NSWorkspace.willSleepNotification`, and restores them on user/display wake, leaving dark wakes suspended. Session presence is authenticated and live-only, using monotonic liveness clocks. Awake heartbeats use 2s/5s; phone screen-off uses 15s/60s, negotiated by `power` frames on both transports. The 5s authentication deadline starts at TCP accept, bounding silent HTTP upgrades, and refreshes when WebSocket is ready. Closing/replacing sessions clears connection handlers and force-cancels the transport. Heartbeats run only with live sessions. Interface changes use `SCDynamicStore` plus a 30s safety sampler; cached addresses preserve split-VPN binding checks. Listener bind retry remains 1s–16s.
- Pairing: Mac **Add Device** QR is `binderclip://pair` with a URL-safe Base64 PSK and up to four sorted IPv4 endpoints (mesh `100.x` first, then LAN, then other unicast). Never advertise loopback. Mesh-first matters because WARP/Tailscale VPNs hijack the LAN subnet with captured routes, so the "LAN" path often tunnels and flaps. Unpairing a phone sends an `unpair` frame first so the phone clears its PSK, then forgets it on the Mac. A later reconnect is ignored until that phone scans the QR again (`pairing` on auth). **Reset pairing key** notifies connected phones the same way, then rotates the PSK.
- Multi-endpoint racing: Android races mesh `100.x`, last-good, then other endpoints with an 8s connection budget. First open claims authentication and cancels other candidates. Failures initially back off 1s–16s, then cap at 60s interactive / 300s screen-off with jitter; heartbeat failures preserve backoff, and 30s of healthy service resets it. Explicit force reconnect bypasses delays. Network changes debounce 2s. A best-effort authenticated Mac sleep notice defers automatic retries for 60s; the lease expires even if a wake notice cannot arrive.
- Dynamic discovery: the Mac advertises its listener as Bonjour `_binderclip._tcp` with TXT `id`/`name`/`v` (re-registered on rename). Android NSD runs only while paired and disconnected (paused while connected and after unpair); a resolved service is accepted only if TXT `id` matches the paired peer id or is absent (legacy), contributes IPv4 non-loopback candidates through the normal merge/racer path, and never overrides PSK auth. NSD re-discovery of an already-known Mac must not reset the WS backoff (it would pin backoff at 1s and starve the Bluetooth fallback); only a genuinely new endpoint resets it.
- Bluetooth fallback: Android BLE central ↔ Mac peripheral, armed when WS is absent/off-network/backoff ≥8s or down >20s. Scan bursts last 8s in balanced/low-power mode with independent 15s→300s cooldown and jitter; user screen-on resets it. GATT/channel/auth setup has a 20s attempt deadline that closes non-null handles, cancels pending L2CAP sockets, and ignores stale callbacks. GATT discovery and acknowledged writes are serialized; GATT sessions are keyed by central identity. Mac advertising runs for missing paired peers or a 120s pairing window, and stops in system sleep. Powered-off manager recovery backs off 30s→300s; denied/unsupported states never retry. GATT receives API 33+ immutable notification snapshots and uses acknowledged writes. Idle GATT uses balanced, screen-off low-power priority; transfers over 16 KiB temporarily request high priority, then restore the idle policy. Receive fragments extend the local deadline, while complete authenticated frames control reverse heartbeat suppression. BT auth_ok advertises endpoints for one forced WS probe; working BT suppresses unattended WS racing and remains until WS is stable for 15s. A new usable network event probes WS while retaining BT. A late BT handshake must retain a live WS connection; Android publishes BT shutdown after the 15s grace period. BT carries text/links, not images.
- Protocol 3 encrypts every application frame over both WS and BLE with PSK-authenticated session setup, HKDF-SHA256 directional keys, and AES-256-GCM ordered counters. There is no plaintext downgrade; both apps must update together, while existing 32-byte pairing keys remain valid. See `docs/secure-protocol.md`. Text/URLs/rename/power are JSON (WS) or CBOR (BLE). Images up to 30 MiB are encrypted binary WS messages containing `[4-byte metadata length]+[JSON header]+[image bytes]`.
- Clipboard classification is fail-closed: file URLs take precedence over TIFF/icons/text, but only supported image files are sent. All other files are ignored and must never be coerced into a filename string.
- Type-tagged single SHA-256 fingerprints prevent clipboard echo loops. A local Mac clipboard change consumes its prior echo marker even when the type or value differs, so copying prior text after an image still sends it. Unpairing clears local paired state while preserving the stable local identity.
- Android requires KernelSU/Magisk root (`RootClipboardBridge.isAvailable()`). Without `su`, the UI is blocked and `BinderClipService` does not run. After root is granted, BinderClip automatically applies `READ_CLIPBOARD_IN_BACKGROUND` and uses clipboard callbacks plus a 3s fallback poll only while paired, interactive, and connected. Image reads are cached by metadata/callback generation with once/minute revalidation; only one poll is in flight, stale reads are discarded, and hashes advance only after delivery is queued. The phone UI lists only the paired Mac; the Mac menu still lists every phone and forwards clipboard/images between them. Android’s share target sends text/images to the Mac; shared `http://`/`https://` URLs use `openUrl` on the Mac. Incoming `openUrl` on Android cannot start a browser from the background service; it posts a **Browser Links** notification that opens the URL on tap. Copying a web URL onto the clipboard stays a `clipboard` frame (no Browser Links notification); `openUrl` is only for the share target and Mac **Send browser tab**. macOS exposes **Services → Send to Phones via BinderClip** (NSServices) to broadcast text, supported images, or URLs to all connected phones.
- Android explicit text and URL shares enter a bounded, Keystore-encrypted outbox before the share activity closes; they drain in order after authenticated WS or Bluetooth reconnection, including after process restart. Unpair/reset clears the outbox. Shared images still require a live WS connection.
- `BinderClipService` is a `specialUse` foreground service (persistent LAN/VPN WebSocket clipboard sync), not `dataSync`, so it is not subject to the Android 15 6-hour timeout and may start after `BOOT_COMPLETED`. `BootReceiver` starts it after boot, OEM quick-boot, or an app update when the phone is paired. After KernelSU/Magisk grants `su`, BinderClip whitelists Doze/AppOps and (while paired) installs `/data/adb/service.d/binderclip.sh` (plus `boot-completed.d` when that directory exists) so OEM autostart blockers cannot drop the service; unpairing removes the script.
- With root, BinderClip applies Doze/AppOps whitelisting and the adb boot keep-alive script automatically (`RootClipboardBridge.ensureAutostart`); the phone UI does not prompt for OEM Auto Start or battery optimization. Notifications and (for Bluetooth fallback) Nearby devices permissions may still be requested in-app.
- On macOS, list blocking Local Network and (macOS 15.4+) denied Clipboard Access at the top of the status menu. Launch at Login is an opt-in under **More**, not a permission nag. Local Network privacy is tracked reliably in distribution only with an Apple-issued signing identity; do not claim a denied/allowed state before Network.framework reports it. The status menu lists phones only (not This Mac); **Reset pairing key**, logs, and updates live under **More**. The status item is template-safe and dims when no session is connected.
- Localization: macOS uses `L10n.tr` with `Resources/<lang>.lproj/Localizable.strings`; Android uses standard `res/values-<lang>/strings.xml` and Compose `stringResource`. Supported languages: English, Indonesian (`id`), Spanish (`es`), Simplified Chinese (`zh`/`zh-Hans`), Japanese (`ja`), German (`de`), French (`fr`), Portuguese (`pt`/`pt-BR`), and Russian (`ru`).
- Store CI credentials in BWS first; GitHub Actions should use only the BWS access token to load project secrets at runtime. Do not commit or print secret values.
- Do not revert unrelated worktree changes.
- Android service shutdown removes the clipboard listener, blocks late work/root callbacks, cancels debounce/polls, and publishes disconnected status without recreating its notification. Poll startup and shutdown share a lock. Diagnostics batch persistence at 2s and flush on controlled shutdown. Fixed-label activity counters report aggregates after 5 minutes of actual work, without extra timers. Never log clipboard content, URLs, PSKs, key fragments, or pairing invitations.
